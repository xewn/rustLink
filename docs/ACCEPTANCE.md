## 高可用与性能

1. 单个 PLC 或 MQTT 不可达时，其他设备与 HTTP 仍能工作。
2. 网络请求具有超时；停止可中断连接、读取和退避；重复启动不产生重复任务。
3. 内存队列有上限；慢 WebSocket/MQTT 消费者不能拖住采集。
4. 配置持久化使用原子替换、备份、写入同步；同路径实例互斥。
5. 主备/集群必须有明确单写者与故障切换证据；单机自动重连不能冒称集群 HA。
6. 实测吞吐、延迟、资源占用；记录环境和负载，不能用 Rust 语言本身代替性能证据。
7. 模拟器测试、原版差分测试和真实硬件验证分开记录；无硬件时不能宣称现场验证。

## 测试资产

- `tools/generate_oracle.py`：加载原版纯逻辑，固定随机种子生成跨语言样本。
- `tests/fixtures/oracle.json`：可审查的原版输出，Rust 测试不需要 Python。
- `tests/compatibility.rs`：配置/地址/解码/倍率与原版逐项对比。
- `tests/fixtures/api_oracle.json`：原版 26 步接口操作序列；`tests/fixtures/*.xlsx`：Excel 对照工作簿。
- `tests/protocols.rs`、`runtime.rs`、`network_services.rs`：协议模拟、网络故障、取消、MQTT、WebSocket 与 AI 流式验证。
- `tests/persistence.rs`、`process_ha.rs`：磁盘故障、并发写入、进程锁、主备接管与退出验证。
- `tests/ui_e2e.py`、`system_differential.py`：真实浏览器操作及原版协议库同源数据对照。
- `examples/simulator.rs`、`tools/benchmark.py`：可独立运行的模拟环境与相同负载性能对照。
- 最终自动化结果和未验证范围见 `VALIDATION.md`；上表是验收范围，不代表每种硬件、无效输入和桌面交互均已穷举。

## 已发现需显式处理的差异

- 原版布尔值也经倍率/偏移转换为数值；应保留。
- 原版 MC 的 uint16 因底层返回有符号字，可能为负数；按真实库行为生成样本。
- 原版断线后调度可能跳过设备导致不再重连；Rust 应恢复，属于可靠性修复。
- 原版 `.xls` 扩展名通过但 openpyxl 无法处理真正的 BIFF 文件；支持扩展必须记录。
- 高可用增强不能更改既有业务消息结构。
